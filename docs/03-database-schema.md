# 03 — Database Schema

Target: PostgreSQL 16+. The schema is also exercised on MySQL 9.7 locally. Types are chosen to be portable.

## 0. Conventions

| Convention | Rule |
|------------|------|
| Primary key | `id bigint generated by default as identity` (Laravel `bigIncrements`) |
| Timestamps | `created_at`, `updated_at` (`timestamptz` in PostgreSQL via Laravel) |
| Soft delete | `deleted_at nullable` only on master data and editable documents; never on ledger/approval history |
| Money | `decimal(18,2)`; unit costs `decimal(18,6)`; currency `char(3)` |
| Quantity | `decimal(18,4)`; conversion factor `decimal(18,6)`; percentage `decimal(7,4)` |
| Status | `varchar(30)` backed by PHP enum; stable sets also get `CHECK` constraints |
| Codes | `varchar(30)` uppercase, unique, immutable |
| FKs | `{singular}_id`; `RESTRICT` for historical integrity, `CASCADE` only for true child records (contacts, lines) |
| Indexes | Every FK indexed; compound indexes for frequent filters; partial unique indexes where soft-deleted uniqueness matters |
| Audit actors | `created_by`, `updated_by`, `approved_by`, `posted_by`, `cancelled_by` → `users.id` nullable, `RESTRICT`/`NULL` |
| Booleans | `boolean NOT NULL DEFAULT false/true` |
| JSON | `jsonb` in PostgreSQL; Laravel `json` maps portably |

`users`, `roles`, `permissions`, `model_has_roles`, `model_has_permissions`, `role_has_permissions`, `activity_log`, `cache`, `jobs`, `failed_jobs`, `sessions` are framework/Spatie tables and are not repeated below.

## 15. Key database invariants

1. `inventory_balances.on_hand_quantity >= 0` and `reserved_quantity >= 0`; `reserved <= on_hand`; `available = on_hand - reserved`.
2. `stock_ledger` has no `updated_at`/`deleted_at`; application DB role has INSERT/SELECT only (production grant).
3. Exactly one of `quantity_in`, `quantity_out` is positive per ledger row.
4. `stock_transactions.idempotency_key` unique.
5. Posted documents (`grn`, `stock_issue`, `stock_adjustment`, `stock_transfer_dispatch/receipt`) have unique posting keys and cannot return to draft.
6. `material_requisition_items.issued_quantity <= approved_quantity <= requested_quantity`.
7. `purchase_order_items.received_quantity <= ordered_quantity` (tolerance handled before persistence).
8. Transfer source ≠ destination; receipt quantity ≤ dispatch quantity.
9. One active approval flow per document type; one active approval request per document.
10. Supplier tax ID unique when present; item code, serial number, batch per item unique.
11. All FK columns indexed; all document numbers unique.
12. Soft-deleted master data remains resolvable by historical documents (FK RESTRICT, no hard delete).
13. One acknowledgement per stock issue (`issue_acknowledgements.stock_issue_id` unique).
14. An issue line cannot exceed the outstanding quantity of its reservation line; posted issues cannot be deleted.
15. Transfer dispatch and receipt totals cannot exceed approved/dispatched quantities; source ≠ destination is a CHECK constraint; missing stock stays in the source warehouse `InTransit` dimension until a discrepancy is resolved.
16. A material return cannot post until every line is assessed and `accepted_quantity + rejected_quantity = returned_quantity`; only good-condition accepted quantities may target an issue-available stock dimension.
